## 放入素材

```text
svc-voice-lab/
  data/target/        # 目标音色歌曲，尽量单人主唱、清晰、少和声
  data/source/        # 待转换歌曲
  data/lyrics/        # 可选：与 source 同名的 UTF-8 校对歌词，供 CER
  .envs/<project>/   # 各项目隔离环境
  models/            # 通过来源/容量/许可证审计的权重
  vendor/            # 后续固定 commit 的官方源码
  .cache/            # 本地依赖/模型缓存
  work/<run-id>/      # 分离、切片、特征、训练等中间产物
  outputs/<run-id>/   # 成品 *_AI.wav、*_mix_AI.wav
  reports/           # 阶段报告和下载台账
  logs/              # 执行和错误日志
  scripts/           # 可复现编排
  config/            # 上游清单、锁定依赖、实验参数
```

换成自己的声音或其他歌，在 `data/target/`、`data/source/` 放入新输入；有多轮素材时用 `--target` / `--source` 显式选择，不把不同歌手混入同一目标集。训练型项目还必须重新预处理/训练并生成索引，零样本项目重新选择参考。用新的 run-id，保留旧 work/outputs 和输入哈希。歌词也随 source 更新；缺歌词不妨碍 SVC，但 CER 不计算。

## 搜索和下载音视频

用户后续授权已替代最初的“禁止自动寻找/下载歌曲”限制。Agent 可直接用下面的入口。使用现有 `yt-dlp`、`ffmpeg`、`ffprobe`，无需安装新依赖；帮助见 `python3 scripts/media.py --help`。

```bash
python3 scripts/media.py doctor
python3 scripts/media.py --public search '周杰倫 晴天 官方 MV' --limit 5

# 可直接只读使用 cc-media 的现有 jar；不复制、不改动原文件。
export SVC_LAB_COOKIE_FILE="$HOME/explorer/cc-media/all_cookies.txt"
python3 scripts/media.py search '陶喆 爱很简单 官方 MV' --platform bilibili
python3 scripts/media.py probe 'https://www.youtube.com/watch?v=DYptgVvkVLQ'

# 选定 URL 后下载；不同批次使用不同 run-id。
python3 scripts/media.py download '<公开视频 URL>' --kind audio \
  --run-id target-001 --role target --purpose '目标音色候选素材'
python3 scripts/media.py download '<公开视频 URL>' --kind audio \
  --run-id source-001 --role source --purpose '待转换歌曲'
python3 scripts/media.py download '<公开视频 URL>' --kind video \
  --run-id reference-001 --purpose '视频参考'
```

Cookie 参数必须放子命令前；也可用 `--cookies /path/to/jar` 或根目录 `all_cookies.txt`。`--public` 强制无 Cookie。它只在仓库外生成短暂私有副本，原文件由用户维护。其他网站可先通过网页搜索获得 URL，再运行 `probe` / `download`。

默认下载保存到 `work/acquisition/<run-id>/`，含原始流、`audio.wav` 或 `video.mkv`、`receipt.json`。指定 `--role target|source` 才额外写入 `data/<role>/<run-id>.wav`；音频保留原采样率/声道，统一格式放在后续预处理。来源探测、搜索、失败证据位于 `reports/evidence/media-events/`。

媒体与模型/依赖共享 30GB 总预算。默认每流最多 500MB，`--max-bytes` 可调整但不超过 5GB。现阶段只下载可确认精确大小的 HTTP(S) 完整流，包括常见 DASH 单文件；HLS 分片、直播、未知大小跳过。视频最高 1080p，音画分离时本地无损封装为 MKV。可搜索/解析不保证平台允许下载；本轮真实验证与限制见 [迁移报告](reports/07_media_acquisition.md)。

## 当前推荐尝试顺序

1. **前处理 + Seed-VC V1 44.1kHz/F0**：目标参考只需短片段，README 明确 Mac 支持，适合先验证。本机已完成隔离 CLI 部署、辅助权重审计和短片段转换；采用 MPS + CPU 混合执行，音色听感仍待人工评价。
2. **Applio**：作为 RVC 训练路线，方便后续做索引和参数对照；需要更多干净目标素材、训练成本及 MPS 训练验证。
3. **so-vits-svc-fork → 原版 RVC → 原版 so-vits-svc**：用于补充对照。当前原版 RVC 主分支针对 Windows/Linux x64；老 so-vits 项目有维护及 Mac 算子风险。
4. **SoulX-Singer-SVC / ReFlow-VAE-SVC**：探索候选。SoulX 现在已有无需歌词/MIDI 的 SVC，但本机依赖/算子尚未验证。GPT-SoVITS 主要为 TTS，不能当作同口径翻唱结果。

Applio-App 是新发现的活跃桌面界面，沿用 Applio 引擎，不重复算成一个独立模型。详细输入、硬件、许可证、stars、完整 SHA 与 issues 见 [调研报告](reports/02_research.md)。以上是**尝试顺序**，不是试听后的音质排名。

清单含历史修复时保留的旧 wheel；它们不会被当前 lock 安装，但仍计入下载。下载器只处理清单，不自行搜索模型；任一文件 >5GB、总预算 >30GB、大小未知、来源不在允许域、哈希不符即停止该项。最终台账见 [downloads.md](reports/downloads.md)。生成新依赖清单时使用目标 venv 的 Python 运行 `scripts/pypi_manifest.py`；该脚本只选择兼容分发文件，不代替依赖解析，离线 pip 安装和 `pip check` 才是最终验证。

当前分离模型和音频已就绪：

```bash
python3 scripts/separate.py --model-repo models/demucs-uvr --model UVR_Demucs_Model_1 \
  --run-id <新批次> --device mps --target data/target/<目标歌手音频> --source data/source/<源歌曲>
```

分离脚本按原曲哈希目录保留 vocals/no_vocals；整理选定 target vocals 到上述独立输入目录后切片。切片脚本只做静音分割、过短筛选和格式统一，**不代表去混响/去和声/伴奏残留审查已完成**。已有片段复现入口 `run_stage2_poc.py`；从 data 开始的编排入口见下文。

## 已发现的坑

- 默认 Python 3.14 对老音频栈不合适；本轮使用现有 3.10.20，不全局装包。
- 沙箱中 MPS=False 不等于硬件不支持，需同一小型测试在本机权限上下文复核。
- Demucs 的旧 Torch 2.0.1 arm64 文件内部 WHEEL 标签错误；最终采用 PyPI 4.0.1 发布包允许的 2.2.2 配对，安装和检查通过。不能把这一适配称作当前 GitHub HEAD 的原样安装。
- Seed-VC 的 README 表格权重链接和推理代码默认文件不同，且首次运行会下载多种辅助模型；必须逐项锁定，不能只审计一个大文件。
- Applio 原安装脚本会使用 Homebrew；本项目不原样执行。Demucs 默认模型域名不在本轮下载入口约定内；现在使用 UVR 程序明确指向的官方 GitHub Release 模型，已完成分离。
- Seed-VC 的 BigVGAN 在 MPS 上触发 grouped conv_transpose1d 通道限制，自动 fallback 不生效；固定声码器到 CPU 后跑通。光谱特征和 RMVPE 也在 CPU，扩散/Whisper/CAMPPlus 在 MPS。
- randomname 的旧 PyPI 元数据漏报 fire，需要按已审计 setup.py 显式补齐依赖；当前 99 项锁定清单离线安装、pip check 均通过。
- 缺校对歌词/抽听时，相应结果写 N/A；不把安装、ASR 或自动检查称为试听。
